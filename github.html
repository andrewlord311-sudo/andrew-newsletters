Things worth trying

Week of 19 October 2026

Five projects this week, and an unusually honest filter behind them. I searched across your range — notes and sync, music, electronics, maths and teaching, web and games, photography, maps — and four of the most appealing things I found had no stated licence, including the one that answers your origami-software question and a browser Arduino emulator with 3,355 stars. They are named at the bottom rather than quietly dropped. What is left is five projects that each have an OSI licence, are all more than a month old, and come with a plain line about what could go wrong. I did not download or run any of it: this is what each project says about itself, checked against who maintains it and how active it is.

Try this weekend

Three things you can try in about an hour each.

yaos

Real-time vault sync on a Cloudflare Worker you own · Mac, Android, iPad

What it is. An Obsidian sync engine built on Yjs CRDTs, so every device holds one live vault state rather than trading files. The server is a Cloudflare Worker you deploy to your own account with a button; text sync works out of the box, and adding R2 storage brings attachment sync and daily snapshots.

Why it is for you. This is the sharpest answer yet to the one problem that spans both your vaults: the Second Brain sitting in iCloud where your Android phone cannot reach it, and the family vault leaning on git with phones that only ever pull. It is also a better shape than the sync plugin here last week — there is no hosted tier, so no encrypted copy of your notes on anyone else's server, and it runs on Cloudflare, which you already use.

To try it. Deploy the Worker from the README's button, click Claim on the Worker URL, install the plugin from Obsidian's marketplace, then scan the QR code on a second device. The README stresses there is no terminal, no .env and no database step. Point it at a throwaway copy of a vault, not the real one. About an hour.

Risk. One developer, eight months old, and the Worker is yours so there is no third party in the middle; no telemetry is mentioned. The limits are specific and worth reading first: without R2 there is no attachment sync and no snapshots, files above the size cap are skipped silently, and empty folders and some non-Markdown plugin files are not covered. The README never tells you to back up first — do it anyway, and never run it alongside iCloud or git on the same vault.

Guitariz Studio

A workbench for guitar and piano in the browser · Mac, iPad, phone

What it is. A web music workbench: chord recognition from audio with the progression exported as MIDI, key and BPM detection, a tuner, stem separation, a scale explorer, a virtual fretboard with a capo, a virtual piano and ear-training drills. React front end, optional Python back end for the audio analysis.

Why it is for you. Two of your stated music goals are writing guitar music and getting back to the piano, and this is aimed squarely between them. The part worth your attention is chord recognition straight out to MIDI: play or load something, get the harmony as a MIDI file, and take it into Reaper. It is also an installable web app, which makes it one of the few music tools on this list that works on the iPad.

To try it. Open the hosted demo and try the fretboard, the scale explorer and a chord analysis on a track you know. Nothing to install. If you want the audio analysis running locally, the back end is a Python virtual environment and a first run downloads a roughly 300 MB Demucs model. About 30 minutes for the hosted tour.

Risk. Small: 35 stars, one named creator, and no stated contributor count — though 18 forks against 35 stars is a healthier ratio than most things this size. The hosted site loads PostHog and Ahrefs analytics, and the README does not say what they collect or where uploaded audio goes, so run the back end yourself for anything you care about. It calls itself an installable web app but never mentions touch support, so treat the iPad as unproven until you open it. Chord-detection accuracy is unverified; nothing here is a substitute for your own ear.

kicad-happy

Design review for electronics, driven from Claude Code · Mac

What it is. A KiCad review toolkit: Python scripts that parse schematics, PCBs and Gerbers into structured data, plus skills that let a coding agent drive them — design review, EMC pre-compliance checks, SPICE simulation, datasheet fetching, component sourcing and fabrication prep. The analysis scripts are pure Python 3.10+ with no required dependencies, and KiCad itself is not needed to run them.

Why it is for you. It was on last week's radar and it has earned a promotion, because electronics is the corner of your range with the least to show for it — a parts inventory that is still a stub and a stated wish to teach the subject. The teaching angle is the real one here: point it at a known-good example board and have it explain what the review found and why, which is a faster route into the vocabulary than reading a datasheet cold.

To try it. Install it as a Claude Code plugin from its marketplace entry, or symlink the skills folder by hand. Then run the analysis scripts against an example KiCad project — no licence keys, and distributor API keys are optional because it falls back to web search. About an hour, and most of that is reading what it reports back.

Risk. MIT, 129 forks behind 1,451 stars, seven months old and actively released. Two honest caveats. It is a skills-plus-scripts toolkit for an agent rather than an application, which is the shape you are usually wary of — the scripts are real, but an agent is doing the driving. And the README never promises read-only operation: its own workflow says to fix issues and re-run, the datasheet skill writes into your project folder, and there is no mention of backups. Work on a copy. Your agent also sends project content to its model provider, and component searches reach out to distributors.

For your projects

Something to learn from rather than install.

Operation Ironhold

A complete 3D game in one 290 KB HTML file · read it, then play it

What it is. A finished first-person shooter that is a single HTML file of about 290 KB. No build step, no asset pipeline, no dependencies beyond three.js from a CDN. Levels are generated procedurally and the sound is Web Audio.

Why it is for you. This is the one to read rather than use, and it speaks to three things you build at once: three.js, the small self-contained pages you send to people as links, and the video pipeline that records HTML scenes and stitches them with ffmpeg. A whole 3D game with no build step is a direct argument about how much machinery that pipeline actually needs, and the Web Audio side is worth a look on its own given your interest in it. The lesson is the file, not the genre.

To try it. Read the source on GitHub — it is one file, so you can scroll the whole architecture in a sitting and see how scene setup, procedural generation and audio are partitioned without a bundler. About 40 minutes to skim properly.

Risk. MIT, 102 stars, 28 forks, and just under three months old — past the one-month line but not by much, so treat it as a thing to study rather than a dependency. It pulls three.js from a CDN, which is fine for reading and worth pinning if you ever borrow the pattern. A single-file 290 KB game is a deliberate stunt as much as a design: admire the partitioning, do not conclude that one file is the right answer for your own projects.

A game

Server Survival

Tower defence, except the towers are infrastructure · browser, iPad

What it is. A 3D browser game in which you play a cloud architect: place and link firewalls, compute, databases and queues to absorb rising traffic and DDoS attacks while watching a budget and a reputation meter. Earn money on requests you serve, lose reputation on the ones you drop; the run ends at zero reputation or minus a thousand dollars. Survival mode, a 25-level campaign and a sandbox.

Why it is for you. Tower defence is the genre you keep coming back to and have built in yourself, and this is the version where the waves are traffic and the towers are capacity planning — close enough to your professional day that the intuitions transfer, far enough to still be a game. It opens in a browser with no account, so it is one of the few picks here that genuinely works on the iPad.

To try it. Open it and play one Survival run, then try the campaign. No install, no build, no account. About 15 minutes to see whether it grips. You can export an architecture as a PNG or share it as a URL, which is a neat touch if you want to show someone a layout.

Risk. MIT by its licence file, though the README itself never mentions a licence. 723 forks behind 6,458 stars is a ratio that holds up, and it is eleven months old with CI on every pull request — but no maintainer is named beyond the account, and the README says nothing about analytics either way. It is a game in a browser tab, so the exposure is small. The cloud architecture it teaches is simplified for play; do not take its scaling lessons to work.

What I left out, and why

The filter, shown working. The rules are in scope/github.md.

  • Four genuinely good projects with no stated licence (rule 2), which is the story of this week. ori-studio, for designing and validating origami models — the closest thing yet to the origami-software question you have had open, and I cannot recommend it. velxio, which emulates Arduino, ESP32 and Raspberry Pi boards in a browser across 19 real boards, at 3,355 stars — it would have been the electronics pick and would have run on the iPad. dolce, a notation editor that reads and writes ABC and MusicXML with offline score recognition. And facet, local AI photo scoring and culling. All four report their licence as NOASSERTION. If any of them adds a real licence, it goes straight in.
  • music-to-midi, MIT and well starred, which converts audio to multitrack MIDI. Ruled out on your kit, not its quality: it needs an NVIDIA GPU with CUDA, explicitly will not fall back to CPU, does not list macOS support at all, and a cold install is about 32 GB of models.
  • Browser ports of commercial games — Morrowind, GTA Vice City and Touhou all surfaced high in the game searches. Copyright-grey, and they expect you to supply game data. (Rule 3.)
  • MCP servers for Logic Pro and FL Studio. Both looked well made; you work in Reaper.
  • A WiFi-sensing repository at roughly 99,000 stars, and others in the same band. I could not separate real interest from bought stars, and nothing in the forks or contributors settled it. (Rule 6.)
  • Everything created in the last 30 days, however well starred. (Rule 1.)
