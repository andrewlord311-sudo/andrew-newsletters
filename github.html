Try this weekend

Three things, three corners of your range, about an hour each.

homr

A photograph of a score, turned into MusicXML · Mac, or the browser demo

What it is. Optical music recognition: point it at a camera photo or a PDF of sheet music and it writes out MusicXML, which MuseScore and anything else in that family will open. It runs locally on the CPU; GPU builds exist for NVIDIA and AMD but are not needed.

Why it is for you. Getting written music off paper and into a file you can manipulate is the oldest unmet want in your music notes, and it sits upstream of nearly everything else — MusicXML opens into MuseScore, out to MIDI, and from there into Reaper. It is also the obvious tool for studying a score you only own on paper: get it into a file and you can transpose it, play it back slowly, or pull one part out on its own.

To try it. Start with the hosted demo and one clean photograph of a page you know well, so you can judge the errors. If it earns a local install, that is uvx --from 'homr[cpu]' homr <image> with Python 3.11 or 3.12 — a single command, no shell pipe, no sudo. About 30 minutes including proofreading what it gives back.

Risk. AGPL-3.0, two and a half years old, 78 forks behind 442 stars and committed to this week — a healthy shape. Three honest caveats. The README never names macOS or Apple Silicon at all; a CPU-only install path exists and nothing suggests a problem, but nobody has told you it works on your machine. It also contradicts itself: the limitations section says it handles pitch and rhythm for treble and bass clefs and skips dynamics, articulation and double accidentals, while the technical section says articulation and dynamics are output. Expect to proofread every bar either way. And the hosted demo means sending your page to someone else's server — fine for a printed edition, worth thinking about for your own manuscript. Model download sizes are not stated anywhere.

Interactive Sudoku Solver

A variant solver that also generates and counts · browser, so the iPad too

What it is. A web-based sudoku engine built for speed rather than for imitating a human solve. It takes grids up to 16×16 including non-square ones, supports a large set of constraints natively and lets you define your own, checks whether a puzzle has a unique solution, and counts solutions (estimating when the count is enormous). There is a JavaScript sandbox for generating and solving puzzles programmatically.

Why it is for you. This is the variant end of sudoku — the Cracking the Cryptic end — rather than another app that deals you a classic grid. Two things in it are worth your evening: uniqueness checking, which is the question you actually want answered when you meet a puzzle off paper, and the scripting sandbox, which is the natural companion to the work you have already done turning paper puzzles into SudokuPad links. Custom constraints mean a variant it has never heard of is still expressible.

To try it. Open the hosted page, enter a grid, add constraints, solve. Nothing to install and no account. If you want it locally it is a Jekyll site you serve yourself. About 20 minutes to find out whether the constraint language fits the way you think.

Risk. MIT by its licence file, though the README never mentions a licence. It is small — 54 stars, 15 forks, one maintainer — but it is six years old and still being committed to this month, which is a far better signal than the star count. The README does not explicitly say that solving happens entirely in your browser: it is a GitHub Pages site with no backend mentioned, no account and no upload step, so that is very likely, but it is inference rather than a promise. It is a solver, not a teacher: it will not show you a human path through a puzzle, and leaning on it will spoil a grid you meant to enjoy.

Local Lens

On-device sorting of a very large photo library · Mac

What it is. A desktop photo organiser that groups a library by face, by where it was taken and by date, with a timeline and search filters. All the recognition runs on the machine; there is no cloud step and no upload.

Why it is for you. The photo library is the part of your range where the problem is volume: tens of thousands of files, the interesting ones buried, and a long-standing wish for culling and search that does not involve handing the lot to a service. Face and place clustering is the cheapest way to make a library that size navigable, and doing it offline is the whole point — this is the one pick here where "local" is the feature rather than a footnote.

To try it. On the Mac, brew install ashesbloom/locallens/local-lens — an ordinary Homebrew install, no shell pipe. Point it at a copy of a folder of a few thousand photos, not the library itself, and see what the clustering makes of it. About an hour, most of it waiting for a first index.

Risk. AGPL-3.0 — the licence file is unambiguous, though the README's own file tree still labels it "MIT License", so the repo contradicts itself on paper. The app is not code-signed: the manual download route tells you to strip the Gatekeeper quarantine flag with xattr and codesign, which is exactly the instruction to be suspicious of in general. The Homebrew route avoids typing those by hand, and that is the one to use. The README says originals are never modified and that nothing leaves the machine, but it never says whether files are copied, moved or indexed where they lie, and it says nothing either way about analytics — hence the copy. One developer, 168 stars against 15 forks, sixteen months old; model sizes are not stated, and it mentions dropping to a lighter detection model when memory runs short.

For your projects

Something to use, not just read — aimed at Roman Colchester.

maplibre-gl-lidar

LiDAR point clouds on a map, in a browser tab · Mac, iPad

What it is. A MapLibre GL JS plugin that draws LiDAR point clouds through deck.gl. It reads LAS 1.0 to 1.4, LAZ, COPC and EPT datasets, colours points by elevation, intensity, classification or RGB, and gives you point picking, a Z offset, an elevation filter and a classification legend. There is a hosted viewer as well as the library.

Why it is for you. This is for Roman Colchester, the project that is paused rather than finished, and it is a use rather than a learn from: the hosted viewer takes a ?url= parameter, so a published LiDAR tile can be opened and turned around without writing a line. The two controls that matter for archaeology are both there — filtering by elevation and colouring by classification are how you separate an earthwork from the tree canopy sitting on top of it. And because it is a browser plugin rather than a desktop GIS, the looking-around part works on the iPad, which is where that kind of thinking actually happens.

To try it. Open the viewer and pass it the URL of a public LAS or LAZ tile for ground you know. npm install maplibre-gl-lidar later if you want it embedded in a page of your own. There is a Docker image too — no use on an ARM NAS that cannot run Docker, so ignore that line. About 45 minutes to learn what the classification colours are telling you.

Risk. MIT, from opengeos — an established geospatial organisation rather than one person, which is the main reason this is a pick and not a radar item. 205 stars, 33 forks, nine months old, still being released. No maintainer is named in the README. The performance caveat is real and specific: non-COPC LAS and LAZ files load in full, with a default budget of a million points, so a large tile will struggle — COPC streams by viewport and is the format to look for. EPT servers must support CORS. Loading is from a URL or a local file in the browser and no upload is mentioned, but the README takes no explicit position on where your data goes, so assume nothing about a third-party tile server.

A game

The Human Box

A civilisation that writes itself · browser, iPad

What it is. A sandbox in which autonomous people form tribes, invent languages, found religions, fight wars, sign treaties and work their way to computers across 45 eras. Nothing is scripted; there are only world laws. You can watch at speeds from paused to 5000×, follow one person and read their life log, or intervene with around 160 tools — reshape land, send a plague, bless a tribe. It is Rust compiled to WebAssembly and runs on your own device.

Why it is for you. It is the history interest and the simulation interest in one tab, and it rewards ten minutes as readily as an hour: set it running fast, then pick a single person and read what happened to them. There is a design argument in it too, for the game work — the whole thing is emergence from rules rather than content that somebody authored, which is the economical answer to "how do you fill a world" that procedural generation keeps promising.

To try it. Open it in a browser. No sign-up, worlds save locally and can be exported, and the page says the client never calls a hosted simulation. 15 minutes to see if it grips.

Risk. Use the browser version and not the desktop download. The macOS install the README offers is a curl … | bash one-liner that also strips the quarantine flag from an unsigned app — precisely the shape of install this newsletter will not recommend. The browser version needs none of it. MIT, five and a half months old, and 63 stars against 5 forks with one developer: the thinnest numbers in this issue, which is tolerable for a browser tab and would not be for anything touching your files. No version number or roadmap is given, so read that long feature list as ambition as much as inventory, and the README says nothing about analytics on the site itself.
